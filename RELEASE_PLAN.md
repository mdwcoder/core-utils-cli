# Release Plan — core-utils-cli

## 1. How releases are generated

Releases are automated via **GitHub Actions**. Pushing a tag matching `v*.*.*` triggers the
`release.yml` workflow. The workflow can also be triggered manually via `workflow_dispatch`.

Each platform job runs on its native runner, builds the binary with **build-time version
injection** (ldflags), packages it into the appropriate format, and uploads it as a workflow
artifact. A final job collects all artifacts, generates SHA256 checksums, and publishes the
GitHub Release.

## 2. Formats

| Platform | Format | File name |
|----------|--------|-----------|
| Linux (amd64) | AppImage | `cu-linux-amd64.AppImage` |
| macOS (universal: amd64 + arm64) | DMG | `cu-macos-universal.dmg` |
| Windows (amd64) | EXE | `cu-windows-amd64.exe` |
| All | Checksums | `checksums.txt` |

Future consideration: `.tar.gz` / `.zip` archives for direct distribution.

## 3. Runners

| Job | Runner | OS |
|-----|--------|----|
| `build-linux` | `ubuntu-latest` | Linux |
| `build-macos` | `macos-latest` | macOS |
| `build-windows` | `windows-latest` | Windows |
| `release` | `ubuntu-latest` | Linux (aggregation) |

## 4. Version injection

Three variables in `internal/config/config.go` are populated at build time via `-ldflags`:

```go
var Version = "dev"
var Commit  = "unknown"
var Date    = "unknown"
```

ldflags used in CI:

```
-X github.com/mdwcoder/core-utils-cli/internal/config.Version=${{ github.ref_name }}
-X github.com/mdwcoder/core-utils-cli/internal/config.Commit=${{ github.sha }}
-X github.com/mdwcoder/core-utils-cli/internal/config.Date=$(date -u +%Y-%m-%dT%H:%M:%SZ)
```

`cu version` output:

```
Core Utils CLI
Version:   v1.0.0
Commit:    abc1234...
Build date: 2026-06-11T00:00:00Z
Platform:  linux/amd64
```

## 5. Checksums

A `checksums.txt` file is generated by the final `release` job using `sha256sum` on
all three artifacts. The file is uploaded alongside the binaries.

## 6. Limitations

### .AppImage
- Requires FUSE on the host or `--appimage-extract-and-run` to execute.
- The placeholder icon is a minimal blue 256x256 PNG generated in CI. A professional
  icon should be added to the repo later.
- AppStream metadata validation is skipped (`--no-appstream`); no AppStream XML is
  embedded.

### .dmg
- **Not signed** (no Apple Developer account / certificate).
- Gatekeeper will block the app on first launch unless the user right-clicks → Open.
- No notarization is performed.
- DMG is created with `hdiutil` (native macOS tool, no external dependencies).

### .exe
- **Not signed** (no code-signing certificate).
- SmartScreen / Windows Defender may show a warning.
- No MSI installer is provided.

## 7. Manual testing

```bash
# Simulate the CI build locally (Linux/macOS):
VERSION=v1.0.0-test COMMIT=$(git rev-parse HEAD) DATE=$(date -u +%Y-%m-%dT%H:%M:%SZ) ./scripts/build.sh
./bin/cu version

# Validate YAML syntax:
python3 -c "import yaml; yaml.safe_load(open('.github/workflows/release.yml'))"

# Or use yamllint:
yamllint .github/workflows/release.yml

# Run tests:
go test ./...

# Check formatting:
gofmt -d .
```
